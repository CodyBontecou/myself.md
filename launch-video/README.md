The current playful cut is 26 seconds, 16:9, 1920×1080, 30 fps, H.264 MP4 with an original synth/percussion score. Actual phone footage shows profile creation, Step Count and app-usage selection, JSON/JSONL settings, saving, and owner approval. A spring-driven agent scene then shows a completed connection, two queries, and visible results: 64,980 steps, a daily average of 9,283, and 352 app minutes. The results hold for six seconds.

Run `npm run video:studio` to edit and scrub. `npm run video:capture-agent` executes an isolated authenticated MCP session and writes `public/agent-transcript.json`. `npm run video:render` regenerates the score, review frames, and `.local/launch-video/myself-md-launch-word-highlight.mp4`; append `-- --stills` for review frames only. The first render downloads Remotion's headless browser. Previous cuts remain as `myself-md-launch.mp4`, `myself-md-launch-dynamic.mp4`, `myself-md-launch-agent.mp4`, `myself-md-launch-playful.mp4`, `myself-md-launch-sound.mp4` and `myself-md-launch-narrated.mp4` in the same output directory.

The agent transcript comes from an actual `@modelcontextprotocol/client` connection to the unchanged production `server/index.js` running locally with a temporary database. The capture script uses a local RS256 identity issuer and a synthetic phone adapter. It creates a real pairing ticket, claims it using the phone identity, publishes the selected profile, verifies a query is denied before consent, and publishes owner-side approval. The agent discovers the catalog, invokes `query_phone_data` twice, and reads completed `get_phone_request` responses. The phone adapter polls the real queue and submits synthetic records through the real result endpoint. Assertions verify dispatch IDs and the exact returned records. The displayed totals are calculated from those responses. Tokens, pairing codes and signing keys are excluded; temporary services and storage are cleaned up.

The video labels this as an actual MCP run with synthetic phone data. The agent presentation is a custom illustrative view of the captured execution, not a recording of ChatGPT or another commercial assistant. For new neural takes, install the optional JavaScript runtime outside the app checkout: `npm install --prefix /tmp/myself-neural-js kokoro-js`. Then run `node scripts/generate-launch-voice.js /tmp/myself-neural-js` and `npm run video:render`. The generator downloads the quantized open model into that runtime's cache and performs inference locally. No script text is sent to a speech service. See the official [Kokoro JS source and usage](https://github.com/hexgrad/kokoro/tree/main/kokoro.js) and [Apache-licensed model card](https://huggingface.co/hexgrad/Kokoro-82M). The model runtime is kept out of phone dependencies.

The word-highlight cut replaces phrase-wide animation with local speech alignment. `scripts/align-launch-captions.js` uses Whisper base.en constrained-transcript DTW against the clean, final-tempo voice takes, checks the recognized words against the script, and stores their boundaries in `public/word-cues.json`. Each active word receives a colored highlight and a spring bounce; future words stay subdued. Connection words receive a larger bounce. Numeric groups track their spoken number/unit words, with a smaller verbatim karaoke line below the large figures. Results cards are slightly shorter to keep both caption rows clear. Rendering verifies the narration SHA-256 against the alignment asset and fails if voice audio changes without updated cues.

To update word timing after regenerating the voice and its stem, run `node scripts/align-launch-captions.js /path/to/ggml-base.en.bin`. This optional step requires `whisper-cli` and the [Whisper base.en model](https://github.com/ggml-org/whisper.cpp#word-level-timestamps); the normal render reuses the retained timing asset. Previous captioned and uncaptioned MP4s remain in `.local/launch-video`.
