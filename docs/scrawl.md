# Scrawl development captures

Physical iPhone testing on October 20 found that active pairing could leave React Native buttons unresponsive while native Back/tab controls worked. React Native required Scrawl's passive window touch observer to fail before delivering presses. The Debug window now installs a forwarding gesture delegate before adding that observer and before touch delivery for later surfaces, removing that dependency only for `ScrawlKit.TouchObserver`. Other gesture decisions still reach React Native's original delegate, and Scrawl's observer and recording trigger remain installed. The first phone candidate still blocked taps after pairing while running; restarting restored them. The revised candidate passed physical pairing-before-first-tap, paired restart, navigation during recording, Send delivery to the Mac, and navigation afterward on October 21; see [QA evidence](argent-qa.md).

The Expo config plugin `plugins/with-scrawl.cjs` links the official ScrawlKit Swift package, pinned to revision `6d4fa333475ef5170c4df683e306480f8618b95a`. It attaches its window observer to the React Native window from the Swift AppDelegate only in Debug, and handles pairing links both in cold-start launch options and the running app's URL callback. It survives `expo prebuild`; do not edit generated iOS files manually.

Run `npx expo prebuild --platform ios`, then `npm run build:ios:debug` (simulator) or `npm run build:ios:device-debug` (device). Debug requires iOS 18; Release keeps Expo's deployment target and does not install Scrawl or handle pairing links. Changes require a fresh native build; an OTA update alone cannot add this SDK.

The saved [pairing touch regression](../.argent/flows/scrawl-pairing-touch-ios.yaml) runs only on a disposable normal Debug simulator with unfinished onboarding, no account and no source permissions. It uses a fictional local pairing configuration, checks ordinary navigation after pairing/re-pairing/restart, and clears that configuration afterward. It passed twice through Argent with fresh services before the first pass. It does not start a recording or verify delivery; never run its pairing reset on an owner's phone.

For a standalone physical-iPhone installation, use the standard [local phone build runner](../../local-phone-builds/README.md) from the canonical local `main` checkout. Run `node src/cli.js start-debug-local` in that runner and poll `npm run status`. The shared MCP operation is `start_debug_build({localOnly: true})`. A completed job must pass signing, registered-phone, embedded-JavaScript and native Scrawl pairing/capture checks before its IPA is installed in place over USB. This mode keeps the IPA on the Mac and cannot publish it. Build completion alone does not establish pairing or a successful capture.

With Scrawl running on your Mac, run `scrawl link --scheme myselfmd` and scan the QR code/open the pairing link on that phone. It contains a private token; do not commit it. Hold three fingers for half a second to start/finish. Approve microphone/local-network prompts when recording and sending. The SDK stays inert on unpaired devices. Open `myselfmd://scrawl?reset=1` to unpair.

On the Mac, use `scrawl inspect latest` or paste with Option-Shift-V. The Mac's `usbApps` list includes `com.myself.md` for USB fallback. Captures can include whatever is visible; no product data grants are changed. This is owner-operated, iOS-only development tooling; ScrawlKit has no Android SDK. On Android use an existing mirror with Scrawl's Mac screen capture.

Scrawl recording and pairing are local developer/OS handoffs, outside the ordinary remote phone-data MCP inventory. The agent can inspect the resulting local `.scrawl` bundle with the Scrawl CLI. Capturing does not authorize agent access to phone datasets or add a new remotely callable recording action.
