# Gripe for React Native / Expo

This local Expo module reuses GripeSDK's UIKit flow in the React Native iOS app. Expo autolinks it during prebuild; no generated native source needs editing. JavaScript calls the bridge through `client/gripe.js`. Android, web and Expo Go report unavailable.

The Swift sources under `ios/vendor/` come from [CodyBontecou/gripe-sdk](https://github.com/CodyBontecou/gripe-sdk), commit `ccf4e1a5d71efe30d53d24601e59c3526ed395fd` (SDK 0.2.1). They retain the upstream MIT license. Local changes gate all SDK source with `DEBUG`, expose the existing capture-in-flight flag to the bridge, emit capture-start/close/submission-failure notifications, and show Next for the initial crop without requiring a drag. The bridge persists bounded operation IDs and outcomes to prevent duplicate capture after a reload, and separates new gesture captures from earlier agent requests. The original success notification supplies the confirmed issue or Gripe receipt URL. No report text or screenshot is sent to the app's agent service.

Configure the ignored `.env` with `GRIPE_API_KEY` and optional `GRIPE_REPOSITORY` (`CodyBontecou/agent-bridge` by default). Run `npm run prebuild -- --platform ios`, then `npm run ios -- --device <simulator-or-phone-id>`. The config plugin injects credentials into generated **Debug** build settings; Release values are empty and native entry points are disabled. Do not use an `EXPO_PUBLIC_` variable for the key. A Debug binary still contains its reporting key, so use a scoped development key. Changing the key requires prebuild and a native rebuild.

Triple-tap with two fingers anywhere, or choose **Settings → Report a bug**. Crop and annotate the screenshot, write the ticket, and submit. `GRIPE_DRY_RUN=1` at prebuild enables a local-only submission simulation; it requires no key and files no issue. Remove that flag and regenerate before live use. SDK transient failures use the upstream on-disk retry queue (25 reports / seven days); check the destination before manually resubmitting after uncertain delivery. MCP's operation ID prevents duplicate capture dispatch, while backend deduplication is available only for the Mac inbox route.

The application MCP exposes `get_phone_feedback`, `request_phone_feedback` and `get_phone_feedback_operation`. The paired foreground phone asks the user before capture, rechecks the request at approval, and uses the same bridge as Settings. The agent receives only status and a confirmed GitHub issue or Gripe receipt URL. A dry run is never reported as a completed ticket. Requests expire after five minutes; retained status is removed five minutes later. Dashboard feedback is not added.

For local Codex execution, see [the Mac bridge guide](../../docs/gripe-mac.md). The success screen shows “Report submitted” and “View receipt” for the trusted Gripe receipt destination. MCP preserves its existing `issueUrl` field for the receipt; completion confirms submission, not a completed fix.

Submission failures show pretty-printed JSON with the actual Gripe error kind, retryability, HTTP status/server payload, or underlying NSError domain/code/cause. The report key is redacted and arbitrary request/userInfo fields are not serialized. Oversized details are explicitly truncated as valid JSON. Native error formatting is exercised by `npm run verify:error-json`; rebuild the Debug app to install this change.
